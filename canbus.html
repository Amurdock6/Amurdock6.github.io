350Z / VQ37 CAN Gateway



service :

Embedded Systems & Protocol Engineering

started :

Fall 2024

completed :

Prototype Validated / In Progress

Connecting a 2003 Nissan 350Z chassis with an engine-swapped 3.7L VQ37VHR powertrain introduced a fundamental communication gap. The older chassis electronics and the newer ECU communicate across disparate CAN bus protocols, message rates, and payload byte layouts. Without an active hardware translator, critical OEM cluster instruments—including vehicle speed, tachometer, and engine coolant temperature—cannot interpret telemetry from the modern powertrain.

I designed and built a dual-CAN automotive gateway in Arduino C++ targeting an ESP32 micro-controller. By combining the ESP32's native TWAI (Two-Wire Automotive Interface) controller with an external MCP2515 SPI CAN transceiver, the gateway physically isolates the chassis and powertrain buses while selectively translating broadcast frames in real time. The firmware includes hardware abstraction layers, explicit timing paces, and gated transmission safety controls.

A core engineering problem in vehicle message translation is preventing stale data from causing erratic vehicle behavior. For speed translation, the gateway monitors source speed packets on CAN ID 0x354 and modifies bytes 4–5 of target frame 0x280 only while source telemetry is fresh within a strict 300 ms window. If source packets drop or time out, target frames pass through untouched. This explicit algorithmic threshold prevents stale values from being broadcast as live sensor readings or triggering drivetrain/ABS faults.

To ensure behavioral parity across firmware migrations without risking live hardware, I developed a Python capture and analysis suite (tools/compare.py) and an offline C++ differential test harness (tests/gauges.cpp). These tools run candidate firmware against recorded wire-level baselines from historical RP2040 implementations, comparing output mappings, source expiry, and message pacing across the entire operational domain before firmware is loaded onto physical hardware.
