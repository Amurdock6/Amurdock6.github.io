View details

Connecting a 2005 Nissan 350Z chassis with an engine-swapped 3.7L VQ37VHR powertrain introduced a fundamental communication gap. The older chassis electronics and the newer ECU communicate across disparate CAN bus protocols, message rates, and payload byte layouts.

Without an active hardware translator, critical OEM cluster instruments—including vehicle speed, tachometer, and engine coolant temperature—cannot interpret telemetry from the modern powertrain. I designed and built a dual-CAN automotive gateway in Arduino C++ targeting an ESP32 micro-controller.

By combining the ESP32's native TWAI (Two-Wire Automotive Interface) controller with an external MCP2515 SPI CAN transceiver, the gateway physically isolates the chassis and powertrain buses while selectively translating broadcast frames in real time. The firmware includes hardware abstraction layers, explicit timing paces, and gated transmission safety controls.

A core engineering problem in vehicle message translation is preventing stale data from causing erratic vehicle behavior.

If source packets drop or time out, target frames pass through untouched. To ensure behavioral parity across firmware migrations without risking live hardware, I developed a Python capture and analysis suite and an offline C++ differential test harness. These tools run candidate firmware against recorded wire-level baselines from historical RP2040 implementations, comparing output mappings, source expiry, and message pacing across the entire operational domain before firmware is loaded onto physical hardware.
