Storefront & API Complete

Protocol Garage is an automotive parts storefront and order management foundation designed to handle e-commerce checkout and asynchronous payment events reliably. Rather than building on an oversized monolithic e-commerce CMS, I built Protocol Garage from the ground up as a high-performance, static-first storefront with edge serverless endpoints engineered specifically for state integrity, checkout idempotency, and graceful partial failure recovery.

The application separates catalog presentation from checkout orchestration, payment handling, and order persistence. The frontend is built using Astro and TypeScript, delivering static product and catalog pages with zero unnecessary client-side JavaScript. Edge API endpoints (/api/checkout and /api/webhooks/stripe) run on Cloudflare Workers backed by a Cloudflare D1 relational database (SQLite at the edge). All cardholder payment entry is delegated directly to Stripe Hosted Checkout, ensuring raw payment credentials never touch application servers.

To prevent race conditions, duplicate charges, or tampering, the checkout service enforces strict server-side catalog validation for all product variants, prices, and quantity limits. Before redirecting to Stripe, the service calculates a deterministic canonical cart fingerprint associated with a client attempt identifier. If a customer retries an identical checkout attempt, the service returns the existing checkout session alongside a stable provider idempotency key; if an attempt identifier is reused with altered cart items, the request is immediately rejected.

Handling payment provider events across distributed systems requires assuming networks will fail, delay, or replay requests. Protocol Garage cryptographically verifies Stripe webhook signatures before claiming events. Using conditional D1 batch transactions, the system explicitly categorizes events as new, duplicate, ignored, or failed. This design guarantees that duplicated webhook deliveries or out-of-order shipment events cannot corrupt order records or trigger double fulfillment. The entire checkout and event lifecycle is validated with Playwright browser tests and automated CI integration suites.
